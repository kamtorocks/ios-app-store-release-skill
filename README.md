# ios-app-store-release

A Claude Code skill for shipping iOS and iPadOS apps through App Review and TestFlight. Three layers:

1. `SKILL.md`: the entry point, loaded automatically when the skill triggers. It routes by situation and lists 11 rules that prevent most rejections.
2. `references/*.md`: field experience distilled into general principles. There is a rejection playbook by guideline, notes on build, upload and version numbers, IAP and subscriptions, Flutter and React Native/Expo specifics, and a submission checklist.
3. `references/official/`: Apple's official documentation archived as Markdown and split by section. The App Review Guidelines take 9 files; 30+ more pages cover privacy manifests, export compliance, account deletion, Sign in with Apple, StoreKit sandbox, server notifications, UIScene and more. Refresh it from the live site at any time.

## Install / update

```bash
git clone https://github.com/kamtorocks/ios-app-store-release-skill.git ~/.claude/skills/ios-app-store-release
git -C ~/.claude/skills/ios-app-store-release pull     # update
```

A skill under `~/.claude/skills/` is user-scoped and available in every project.

Requirements: macOS, `python3` (standard library only), and Xcode Command Line Tools (`otool` and `codesign`, used by `inspect_ipa.py`).

## Scripts

```bash
S=~/.claude/skills/ios-app-store-release/scripts
python3 $S/apple_docs.py status                          # archive freshness
python3 $S/apple_docs.py sync --diff                     # refresh all archived docs, print what changed
python3 $S/apple_docs.py guideline "5.1.1(v)" "3.1.2(c)" # exact guideline text (quote refs in zsh)
python3 $S/apple_docs.py news --days 90                  # Apple Developer News: new requirements, deadlines
python3 $S/apple_docs.py fetch https://developer.apple.com/documentation/...  # any Apple page → Markdown, including JS-rendered DocC pages
python3 $S/inspect_ipa.py build/ios/ipa/App.ipa          # inspect an IPA as App Review sees it
```

`inspect_ipa.py` cross-checks purpose strings against linked frameworks in both directions, and reports entitlements, privacy manifests, the export-compliance key and UIScene adoption.

To archive another official page, add an entry to `references/official/sources.json` and run `sync <id>`. `INDEX.md` is generated by `sync`; don't edit it by hand.

## Contributing lessons

When any project resolves a new rejection, ITMS error, App Review question or new-iOS breakage, add it to the matching `references/*.md`. Write it as reviewer wording → mechanism → fix → prevention, and keep only the generalized principle.

Project names, bundle IDs, product names and project paths stay in that project's own docs. Before committing, check that no secrets, Team IDs or device IDs are included.
